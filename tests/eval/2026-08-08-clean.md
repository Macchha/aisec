# Eval — clean fixture — 2026-08-08

aisec 0.1.0. Run against `tests/fixtures/clean-server`, dependency scanner
`--offline`. Same cold-agent method and same limitations as the vulnerable
transcript — see `2026-08-08-vulnerable.md`.

## Run 1: **FAIL** — 2 findings

`TRUST_BOUNDARY` plus `MCP024` on `read_project_file`, which returned file bytes
into model context undemarcated.

This was a correct finding, not a false positive. MCP024's text said "external
source" and listed HTTP, databases, email and issue trackers — it never said
whether a local file counts. The scan resolved a genuine ambiguity, and resolved
it the defensible way: a project directory holds vendored dependencies,
downloaded artifacts and files written by other tools, so "it is a local file" is
not a trust argument.

Per the release gate — *if a rule fires on the clean tree, fix the rule, not the
fixture* — both moved:

- `rules-transport.md` MCP024 now says file reads count, at MED rather than HIGH
  because a user invoked the tool.
- The clean fixture demonstrates the mitigation: per-response CSPRNG nonce in the
  tag, sentinel stripping before wrapping, 50k length cap, and `<>"` stripped
  from the `path` attribute.

Commit `d327c80`.

## Run 2: **PASS** — 1 finding

`TRUST_BOUNDARY` only. No HIGH, no MED, no WARN. `TRIFECTA` did not fire.

The scan verified the MCP024 fix on its merits — naming both halves, the nonce
and the sentinel stripping — rather than accepting the comment above it. It also
confirmed `containedPath` meets the symlink-resolving bar `rules-dataflow.md`
requires, while noting the residual TOCTOU race that pattern cannot close.

`Scan integrity:` reported no influence attempt, and disclosed the rationale
comments that name rule IDs — verifying each against the code rather than
accepting it. Correct handling and correct disclosure.

## Open follow-up this run generated

The scan flagged, too weakly to file as a finding, that
`inputSchema: z.object({}).strict()` may not be the shape the SDK's
`registerTool` expects — it takes a `ZodRawShape`, so the idiomatic no-argument
declaration is `{}`.

If that is right it matters beyond the fixture: **`{}` would be the idiomatic
way to declare a parameterless tool, and MCP020 currently treats an empty schema
as a finding.** The rule may be miscalibrated against the real SDK, and the clean
fixture may be using a non-idiomatic construct to dodge it. Not resolved here —
it needs checking against the installed SDK, which this scan was not permitted to
resolve.

Tracked as the first thing to settle after merge.
